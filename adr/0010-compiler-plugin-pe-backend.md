# ADR 0010: Прямая генерация PE в compiler-plugin (замена IL-текста + ilasm)

- **Дата:** 2026-08-22
- **Статус:** Proposed
- **Связанные:** ADR 0001 (заменяемый pipeline), ADR 0009 (порт dotnetutils),
  [COMPILER-INTEGRATION.md](../TODO/I-dotnetutils/plan/COMPILER-INTEGRATION.md)

## Контекст

После завершения порта dotnetutils (I0–I7, майлстон M1: hello-world EXE,
собранный чисто Kotlin-кодом, проходит запуск через `dotnet`,
C#-harness на настоящем SRM и dotnet-ildasm) у проекта есть два пути
генерации сборки:

1. **Текущий (ADR 0001):** IR → CIL-текст → внешний процесс ilasm → PE.
2. **Новый:** IR → MetadataBuilder/InstructionEncoder/ManagedPEBuilder
   (модуль dotnetutils) → PE.

Ограничения пути №1 уже сформулированы в ADR 0001 и ADR 0009:
хрупкость текстового формата (экранирование имён, совпадающих с
опкодами), лишний процесс и повторный парсинг, диагностика ошибок
формата только текстом ilasm.

## Решение

Перевести compiler-plugin на путь №2, сохранив путь №1 как fallback до
стабилизации:

- новая CLI-опция плагина `backend` со значениями `il` (дефолт) и `pe`;
- при `backend=pe` IR-обход (`DotnetIrVisitor`) пишет не в
  `TextIlEmitter`, а в новый PE-эмиттер поверх
  `MetadataBuilder` + `InstructionEncoder` + `ControlFlowBuilder`;
- `kotlinc-net.sh` по значению флага пропускает шаг ilasm;
- после зелёного прогона всей e2e-сетки на новом пути дефолт
  переключается на `pe`, текстовый эмиттер удаляется.

## Отклонения и упрощения относительно SRM

Унаследованные от порта (см. шапки файлов dotnetutils): только
write-path; отсечены EnC/WinMD/PDB/DebugDirectory. Новых отклонений
интеграция не вводит.

## Последствия

+ Исчезает внешняя зависимость от ilasm (NuGet-тул) из критического пути.
+ Ошибки структуры метаданных ловятся в момент генерации.
+ Спецмассивы и дженерики в будущем становятся проще (reified generics
  CLR + BlobEncoders вместо ручного текста).
− Двойная поддержка двух бэкендов на переходный период (ограничена
  декомпозицией S1–S6 интеграционного плана).
− Метаданные (таблицы, ссылки на runtime), которые раньше строил ilasm,
  теперь строим сами — это основная новая поверхность ошибок.

## Проверка решения

Критерии приёмки каждого шага — в COMPILER-INTEGRATION.md. Итоговая
точка: вся e2e-сетка (`just test all`) зелёная без вызова ilasm.
