# ADR 0001: Pipeline — IR → IL-текст → ilasm → .NET-сборка

- **Дата:** 2026-08-17
- **Статус:** Superseded — IL-текстовая ветка удалена; см.
  [0010](0010-compiler-plugin-pe-backend.md) и [0012](0012-remove-il-text-path.md)

## Контекст

Нужно превратить Kotlin IR (intermediate representation K2 компилятора) в
исполняемую .NET-сборку. Возможные подходы:

1. **IR → бинарный PE/CIL** (эмуляция System.Reflection.Emit из JVM,
   ручная запись PE-заголовков).
2. **IR → IL-текст → ilasm** (текстовый CIL, внешняя утилита `ilasm`
   из .NET SDK компилирует в сборку).
3. **IR → сериализация → отдельная C#-утилита** через dnlib или
   System.Reflection.Metadata.

## Решение

**Вариант 2: IR → IL-текст → ilasm.**

## Почему

- **Не нужно** реализовывать бинарный PE/CIL формат на Java — `ilasm`
  делает это за нас.
- IL-текст человекочитаем — критично для отладки на этапе PoC.
- Весь pipeline работает в одном процессе (JVM) + один вызов внешней
  утилиты (`ilasm`).
- `ilasm` доступен в .NET SDK на всех платформах (Windows, Linux, macOS).
- Запасной вариант (3) оставлен на случай, если перехват IR через
  compiler plugin окажется невозможным.

## Последствия

- Плагин генерирует строку (IL-текст) и пишет её в `.il`-файл.
- Сборка финальной DLL/EXE — отдельный шаг через `ilasm` подпроцесс
  (или shell-обёртка).
- Для сложных конструкций, требующих бинарных метаданных (например,
  GenericParamAttributes), IL-синтаксис покрывает всё необходимое.
