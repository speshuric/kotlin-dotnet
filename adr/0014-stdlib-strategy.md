# 0014. Стратегия stdlib для таргета .NET

- **Статус:** Accepted
- **Дата:** 2026-08-27
- **Дизайн-документ:** [`docs/stdlib-design.md`](../docs/stdlib-design.md)
- **План реализации:** [`TODO/D-stdlib/D-03-stdlib-implementation-plan.md`](../TODO/D-stdlib/D-03-stdlib-implementation-plan.md)

## Контекст

Источник деклараций stdlib для пользовательского кода — родной
kotlin-stdlib на classpath kotlinc. Плагин перехватывает только известные
вызовы (`StdlibResolver`); остальное из `kotlin.*` уходит в неразрешимые
JVM-тела или молча теряется. Поверхность API не контролируется. Для
трека мэппинга имён (F) нужны собственные трансляционные аннотации, которым
требуется место в компилируемом Kotlin-коде. Образец организации —
upstream `libraries/stdlib` (common + js), включая шимы `println` поверх
платформенного примитива и механизм неявных импортов
(`DefaultImportsProvider`, список пакетов не зависит от модуля-источника).

## Решение

1. **Модель — гибрид A→B.** Этап A: родной classpath остаётся источником
   сигнатур; перенаправления живут в реестре плагина; добавляется учёт
   покрытия и режимы строгости. Параллельно строится каркас собственного
   stdlib (`kotlin-dotnet-engine/libraries/stdlib`). Этап B: наш stdlib-jar
   подставляется вместо родного через `kotlinc -Xno-stdlib -cp <наш>.jar`;
   переключатель — фича-флаг скрипта (`--own-stdlib`), не языка.
   Смешанное состояние (обе stdlib на одном classpath) невозможно —
   redeclaration.
2. **Таблица переносов — целевая форма: аннотации на шимах.** Плагин читает
   их из IR (`IrAnnotationContainer.annotations`; значение — IrConst).
   Переходно (этап A) — декларативный реестр `StdlibMapping.kt` с теми же
   полями записи (fqn, сигнатура, target), чтобы конвертация реестра в
   аннотации была механической.
3. **Политика неперехваченных вызовов:** CLI-опция `stdlib.mode=strict|lenient`.
   Strict (целевой дефолт) — ошибка компиляции со сводным списком символов;
   lenient — предупреждения. Тихие заглушки запрещены.
4. **Раскладка каркаса:** один Gradle-модуль, пакеты зеркалируют upstream
   (`kotlin/io`, `kotlin/text`, `kotlin/collections`) плюс наши
   `kotlin/dotnet/annotations`; без expect/actual (таргет один).

Наши трансляционные аннотации на этом шаге НЕ эмитируются в метаданные
(смысл — инструкция компилятору); эмиссия CustomAttribute — обобщение
`addCustomAttribute` по плану F-03 слой 0.2.

## Последствия

- (+) Контролируемая поверхность API и честные ошибки вместо тихих дыр.
- (+) Механизм неявных импортов продолжает работать без изменений фронта,
  пока пакеты наших деклараций совпадают с upstream.
- (−) Этап B требует поддержки минимума Intrinsics (диапазоны, `listOf`,
  enum entries); ориентир объёма — каталоги `*-minimal-for-test` апстрима.
- (−) Переходное двойное состояние «реестр + аннотации» живёт до шага 6
  плана; реестр удаляется после миграции шимов.
