# 0012. Удаление IL-текстового пути (ilasm)

- **Статус:** Accepted (реализация — Phase 10.9)
- **Дата:** 2026-08-24
- **Supersedes:** частично [0001](0001-pipeline-ir-to-il.md) (пайплайн
  IR → .il → ilasm); развивает [0010](0010-compiler-plugin-pe-backend.md)

## Контекст

PeIlEmitter (ADR 0010) полностью вытеснил текстовый путь функционально:
вся сетка e2e-тестов зелёная на pe, включая классы (Phase 10).
TextIlEmitter заморожен на возможностях Phase 9 (классы не поддерживает)
и состоит из заглушек TODO. Поддержка двух путей эмиссии удваивает
поверхность: CLI-опция `backend`, экранирование CIL-слов ради парсера
ilasm, swap-логика для dll-консьюмеров, внешний инструмент ilasm-cli.

## Решение

Удалить IL-текстовый путь целиком: TextIlEmitter, IlContext, контрактные
тесты, CLI-опцию `backend`, il-ветки сборочных скриптов, установку
ilasm-cli, экранирование CIL-слов. Единственный формат вывода
компилятора — PE через dotnetutils.

## Следствия

- «+» один путь эмиссии; упрощение контракта IlEmitter (без `text()`/
  `beginStaticMethod`); build-test.sh без swap для dll-консьюмеров;
  минус внешний инструмент ilasm.
- «−» исчезает читаемый промежуточный `.il` как артефакт отладки —
  заменяется дизассемблированием PE через dotnet-ildasm
  (справочник: [docs/il-reference.md](../docs/il-reference.md)).
- «−» инкрементальность по mtime(`.il`) пропадает (pe всегда пересобирает).
- «−» внешние вызовы с `backend=il` начнут падать с понятной ошибкой
  (fail-fast, осознанно).
