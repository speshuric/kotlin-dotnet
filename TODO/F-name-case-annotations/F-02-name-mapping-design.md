# F-02: Проектирование мэппинга имён (объединяющая задача)

- **Тема:** F. Names
- **Разметка:** POST-10 (проектирование), реализация — по частям
- **Зависимости:** F-01 (аннотации PascalCase/camelCase), Phase 10
  (коллизии операторных имён), ADR 0005 (verbatim PoC-мэппинг)
- **Статус:** TODO

## Контекст

К Phase 10 накопилось несколько точечных решений вокруг имён, каждое из
которых локально разумно, но вместе они образуют несистемную картину.
Пора спроектировать **единый мэппинг имён** Kotlin → .NET до того, как
фичи языка разойдутся дальше.

## Триггеры (факты из Phase 10)

1. **Коллизии operator-имён**: пользовательский `class Counter { fun inc() }`
   попадал в операторную ветку visitor'а (`c.inc()` компилировался как
   `c + 1`). Костыльное различение по пакету callee (`kotlin.*` vs свой)
   работает, но это эвристика в кодогенераторе. См. TODO/PHASE-10.md
   §«Итоги» п.5.
2. **Экранирование CIL-зарезервированных слов**: устранено в Phase 10.9 —
   с удалением ilasm-пути (ADR 0012) `NameMapper.methodName` возвращает
   имя verbatim, метаданные пишутся напрямую.
3. **Имена аксессоров**: дефолтные аксессоры пишутся в метаданные verbatim
   (`<get-x>`). Валидно для CLR, но неидиоматично для .NET-интеропа
   (csc-стиль: `get_X`); C#-потребители увидят методы с угловыми скобками.
4. **Имена модулей**: moduleName = assembly name без расширения; у ilasm/
   csc модуль именуется с `.dll`/`.exe` (на работу не влияет, но
   отличается в дампах).
5. F-01: аннотации `@kotlinToPascalCase` / `@dotnetFromPascalCase` /
   `@DotnetName` — пока вообще не проектировались.

## Что спроектировать

1. Единая таблица «Kotlin-сущность → CLR-имя»: классы, топ-левел функции
   (контейнер `<File>Kt`), методы, аксессоры (стиль `get_X` vs `<get-x>`),
   поля (бэкинг-поле), параметры, сборка/модуль.
2. Политика для коллизий с CIL-словами и опкодами (замена экранирования
   кавычками; например, суффикс/префикс или проверяемый белый список).
3. Механизм распознавания stdlib/operator-вызовов, не зависящий от
   пакета callee (например, маркерные origin'ы/аннотации или отдельная
   таблица символов runtime).
4. Интеграция с F-01: где живут аннотации, как хранятся альтернативные
   имена, обратный маппинг для импорта BCL.
5. Совместимость уже выпущенных тестовых образов (реестр ожиданий).

## Результат

ADR (новый, рядом с ADR 0005) + рефакторинг NameMapper/StdlibResolver +
устранение эвристики `kotlin.*` из `emitCall`.

## Приёмка

- Нет обращений к `callee.kotlinFqName.startsWith("kotlin.")` в
  кодогенераторе (проверка через grep).
- Тест с пользовательскими методами `plus`, `inc`, `box`, `add` — зелёный.
- Решение по аксессорам зафиксировано (верbatim или `get_X`) и отражено
  в дампах verifier'а.
