# F-03: Спецификация маппинга идентификаторов Kotlin ↔ .NET

- **Статус:** TODO (черновик спецификации готов, см. ниже)
- **Разметка:** POST-PoC (дизайн; имплементация после стабилизации фаз
  языка 10–13)
- **Зависимости:** F-01, F-02, Phase 10 (классы), Phase 13 (companion,
  object, enums)
- **Связанные:** AGENTS.md §«Маппинг типов», ADR 0005 (NameMapping)

## Что сделать

1. Ревью и дополнение черновой спецификации
   `docs/identifier-mapping.md` (текст ниже — исходный набросок от
   пользователя; подлежит вычитке, проверке на полноту таблицы и
   согласованность с реализацией по мере роста фаз).
2. Имплементация механизма `KotlinIdentifierAttribute` (v0.01: имя +
   schemaVersion) в кодогенераторе — после Phase 13.
3. Имплементация `@DotnetName` — manual override для callable-из-C# имён.
4. Детектор коллизий после camelCase→PascalCase — безусловный, на этапе
   компиляции (см. раздел «Прецеденты» в спеке).
5. Верификация round-trip: экспорт Kotlin→.NET→импорт .NET→Kotlin
   восстанавливает исходные имена (через атрибут или эвристику).

## Открытые вопросы (из спеки)

- Companion-дискриминатор в v0.01 (эвристика по имени `Companion` или
  явный бит).
- Названия scope-level переключателей.
- CLS-совместимость сборки (`[CLSCompliant(true)]`) — заявлять ли.
- Подтвердить совпадение границ «модуль» Kotlin и «сборка» .NET в модели
  компилятора (для `internal`).
