- **Тема:** I. dotnetutils (порт SRM)

## Конечная цель

Независимый Gradle-модуль `kotlin-dotnet-engine/dotnetutils`
(`org.kotlindotnet.dotnetutils`), обеспечивающий полный цикл создания
.NET-сборок (PE DLL/EXE) из Kotlin: перенос write-path
`System.Reflection.Metadata` из dotnet/runtime. В перспективе — замена
шага «IL-текст → ilasm» в pipeline компилятора на прямую генерацию PE.

Ключевые ограничения (детали и обоснование — в ADR 0009):

- чистый kotlin-stdlib, прямые `import java.*` запрещены;
- API близко к оригиналу (неймспейсы → пакеты), именование — Kotlin;
- отсечены: EnC, WinMD, Portable PDB/embedded PDB;
- верификация: юнит-тесты + C#-harness на настоящем SRM; позже —
  минимальный MetadataReader на Kotlin.

## Этапы работ

1. **Подготовка** — ✅ выполнено: структура `kotlin-dotnet-engine/`,
   скелет модуля собирается (см. CHANGELOG).
2. **Анализ сборки** (каждый пункт — отдельный согласуемый коммит):
   - список namespaces/API, нужных для write-path — утвердить;
   - карта зависимостей C#→Kotlin (коллекции, потоки, MemoryMarshal…)
     с классификацией «аналог в kotlin / перенос / обёртка» — согласовать;
   - минимальный публичный API для переноса: до класса/интерфейса,
     публичные методы по умолчанию все; составить и зафиксировать;
   - оценка реализуемости → переход к планированию.
3. **Планирование реализации**: иерархический план небольшими шагами
   (~до 10 000 строк C# за итерацию): сначала публичные сигнатуры,
   затем тесты блока, затем функциональное мясо. План закоммитить в
   удобном для трекинга виде (этот файл + подпапка `plan/` при росте).
4. **Поэтапное выполнение**: параллельные агенты с ограниченным
   контекстом; логически целостные блоки, проходящие тесты — коммит
   (по согласованию).
5. **Внедрение в compiler-plugin**: план перевода генерации на новый
   процесс (без ilasm), отдельный процесс фиксации (TODO-шки по
   согласованию); миграция существующих тестов.
