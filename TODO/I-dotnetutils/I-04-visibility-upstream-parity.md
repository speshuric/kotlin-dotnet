## Принципы

1. **Публичный API Kotlin-SRM повторяет апстримный SMR максимально
   точно** — имена типов/методов/параметров, сигнатуры, состав
   перегрузок. Оговорки допускаются только там, где от чего-то явно
   отказались (EnC, WinMD, DebugDirectory, …) — и каждая такая
   вырезка задокументирована в шапке файла (раздел Deviations).
2. **Internal API должен быть разумно похожим на апстримный**: даже
   не попадая в публичную поверхность, внутренние типы/функции должны
   узнаваться при сравнении с оригиналом, чтобы при обновлении базы
   дельта находилась механическим диффом, а не реконструкцией.
3. **Наименьшая возможная видимость** для всех типов, полей, методов:
   `private` → `internal` → `public`, повышать только по необходимости.
   Апстримный аналог — первичный ориентир (`private`-члены класса
   в C# ≈ top-level `private` в Kotlin, если использование не выходит
   за файл).
4. **Тесты**: портировать кейсы из `dotnet/runtime`
   (`tests/Metadata/Ecma335`, `tests/PortableExecutable`) рядом с
   собственными smoke; на каждом ревью снова сверять покрытие — какие
   апстримные тесты ещё не перенесены для затронутых файлов.

## Конкретика (стартовый срез)

- `MetadataBuilderSerializer.kt`: 35 табличных `serializeXxxTable`
  остались `internal` по конвенции раннего порта, хотя в апстриме это
  `private`-члены партишл-класса. Диспетчер лежит в том же файле ⇒
  им достаточно `private` (образец — четыре debug-сериализатора,
  переведённые в `private`).
- Grep-критерий завершения прохода: в `ecma335/` не осталось
  `internal fun`/`internal val`, чьи использования ограничены одним
  файлом.

## Мотивация

Чем точнее зеркало (публичный API + внутренняя структура + видимость),
тем механичнее проходит merge дельт из dotnet/runtime и тем меньше
шансов молча разойтись семантикой.
